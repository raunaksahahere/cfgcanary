**cfgcanary v0.1.0** is the first release: an **alpha**. It is complete for the scope in
[docs/requirements.md](https://github.com/raunaksahahere/cfgcanary/blob/v0.1.0/docs/requirements.md)
and tested against real PostgreSQL, S3, Prometheus and Toxiproxy, but it has not run in production.

Progressive delivery for configuration: validate, canary, promote and roll back config like code.

## What's in it

- **Validation before anything ships**: byte and cardinality limits, strict JSON, JSON Schema, CUE,
  relative-change guards, and the consumer's own parser run as WASM in a wazero sandbox. Rejected
  versions reach no instance.
- **Ring-by-ring delivery** with a Prometheus health gate (three-zone harm and non-inferiority tests,
  instance-clustered variance, error split over predeclared looks). Missing evidence never promotes.
- **Automatic rollback** on gate failure, SDK rejections or crash loops; an audited break-glass kill
  switch.
- **Safe consumers**: agents verify ed25519-signed artifacts and delivery statements and write a
  crash-consistent cache; the Go SDK serves immutable snapshots and keeps last-known-good.
- **One durable authority** (PostgreSQL) with fenced controller leadership, mTLS identities and RBAC.
- **Kubernetes**: `ConfigRelease` CRD, per-ring ConfigMaps, Helm chart.

## Install

Download the archive for your platform below, check it against `SHA256SUMS`, and run `cfgcanary version`.

```bash
curl -fsSLO https://github.com/raunaksahahere/cfgcanary/releases/download/v0.1.0/cfgcanary_0.1.0_linux_amd64.tar.gz
curl -fsSLO https://github.com/raunaksahahere/cfgcanary/releases/download/v0.1.0/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf cfgcanary_0.1.0_linux_amd64.tar.gz && ./cfgcanary_0.1.0_linux_amd64/cfgcanary version
```

Container image: `ghcr.io/raunaksahahere/cfgcanary:v0.1.0` (linux/amd64, linux/arm64).
Go SDK: `go get github.com/raunaksahahere/cfgcanary/sdk@v0.1.0`.

Each archive was executed on its native GitHub runner (Linux x64 and ARM, macOS ARM and Intel)
before this release was published.

## Evidence

Measured on one laptop ([method and limits](https://github.com/raunaksahahere/cfgcanary/blob/v0.1.0/docs/benchmarks.md)):
a runtime-harmful change reached 8 of 50 instances (the canary ring) and was rolled back in under
0.1 s after detection, versus 50/50 with naive push; 0 agent or SDK crashes across 12 chaos
scenarios; per-ring delivery at 1,000 agents p99 under 0.71 s (received) on a single host.

## Compatibility

Alpha: the API (`cfgcanary.v1`) only adds fields, statement formats are versioned, but CLI, SDK,
chart and CRD may change in 0.x minor releases. Upgrade the control plane before agents.
See [compatibility](https://github.com/raunaksahahere/cfgcanary/blob/v0.1.0/docs/compatibility.md).

## Known limitations

- Disconnected instances are rolled back when they reconnect, not before.
- Small canaries (about 5 instances) or low traffic mostly halt the gate rather than decide; use a
  `hard_max` for severe failures.
- Kubernetes ConfigMap delivery inherits kubelet's sync delay; payloads are limited to 1 MiB there.
- Tested end to end on Linux; macOS binaries are cross-compiled and smoke-tested on native runners.
- Not yet built (documented future work): Argo Rollouts analysis, OpenFeature provider, multi-region
  rings, automated bake-time tuning.
